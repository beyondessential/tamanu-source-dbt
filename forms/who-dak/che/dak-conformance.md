# DAK conformance — child health

What these forms take from the WHO DAK for child health (0–59 months) in humanitarian emergencies,
what they deliberately do differently, and what the DAK specifies that a Tamanu form cannot hold.

## Source

Everything is generated by [`../dak_generator.py`](../dak_generator.py) from the kit's **core data
dictionary** (`CCC DAK_core data dictionary.xlsx`, 531 labelled rows across 15 clinical tabs). It
gives each data element an ID (`CHE.B7.DE01`), a label, a data type, a `Required` flag,
terminology codes (ICD-11 / ICD-10 / LOINC / SNOMED CT / ICHI / ICF) and — for coded elements —
one child row per input option.

Twenty-six further rows come from the **decision-support logic**. Nothing is authored by hand.

**This kit is not published as IRIS Web Annexes.** IRIS carries the PDF and WHO ships the four
components through its SMART guidelines implementation guide at
[smart.who.int/dak-ccc](https://smart.who.int/dak-ccc/). The component pages there serve whatever
the site last built, so [`domain.py`](domain.py) pins each component to WHO's own source
repository for that guide — `WorldHealthOrganization/smart-dak-ccc` — at the **`v1.0.0` tag**,
whose `sushi-config.yaml` declares `status: active` and `releaseLabel: release`. That is a
version-pinned path to the released bytes, which the component page is not; the component page is
recorded alongside it as `page`.

**The repository slug and the kit's identifiers disagree.** WHO names the repository
`smart-dak-ccc` and titles the guide `SMART DAK CCC`; nothing inside the kit says `CCC` anywhere.
Every tab is `CHE.*`, every data element is `CHE.*.DE*`, every indicator is `CHE.IND.*`. The
directory, the program code and the question codes follow the identifiers.

## What the forms are

Thirteen surveys: 200 questions from the dictionary, 17 of them classification questions this
reader builds from the kit's own rows, plus 26 decision-support rows from Annex B. The survey
table is in [`README.md`](README.md) § The forms.

Four rules of the reader are this kit's, and each is described where it lives in
`dak_generator.py`.

### The header is not the first row

Every other kit opens a tab with its column headers. This one puts three or four banner rows above
them — the kit's title, the business process, the tab's own name, each a single merged cell — and
so heads most of its tabs at row 4 and `CHE.B6.Measurements` and `CHE.B.26.Population-HIV` at row
5. Read from row 1, no column matches and every tab comes back as unlabelled rows holding nothing.
The header is now found by looking for the column every kit names, `Data element label`.

### The `Required` legend, spelled four ways

The flag column is headed `Required (R)/optional (O)/conditional (C)` — except on
`CHE.A.Registration`, which puts a space after the second slash; on
`CHE.B7-9.LTI-DangerSigns`, which puts one before it; and on `CHE.B25.Population-Malaria`, which
drops the `(O)` altogether. Four spellings of one legend on one kit, differing only inside the
brackets.

Answering them one spelling at a time invites a fifth to pass unnoticed, and a `Required` column
matching nothing does not fail — it silently drops every mandatory flag on the tab. A header is
therefore also indexed under whatever precedes its parenthesised legend.

### Option rows marked as something else

Twenty-three of the kit's option rows qualify the mark in place rather than in the conditionality
column beside it: `Input option (for type of skin problem)`,
`Input option (automated based on weight measurement)`,
`Input option (dependent on integer) – Alert pop up box`. Sixteen more carry the parent's own mark
instead: `CHE.B7.DE03A Select all danger signs that apply` is `Coding` / `Select all that apply`,
and its five options — convulsions in this illness, unconscious or lethargic, not able to drink or
breastfeed — are typed `Codes` and marked `Select all that apply` too.

Read as written, the danger-sign list imports with no options at all and its five options become
mandatory-looking questions of their own. Both are now recognised: the qualifier is stripped
before the mark is matched, and a `Codes` row repeating the mark of the parent still open above it
is that parent's option.

### The bullet in the option cell

This kit writes each option row's `Input Options` cell as an item of a bullet list — `- One
convulsion`, `- Vomiting everything` — and one row kept the apostrophe Excel uses to force a cell
to text: `'- Entered response in error`. 187 of the kit's 261 options carry a bullet; no other
kit's carry any.

The bullet is layout, not answer. These strings land in `survey_response_answers.body` and Annex B
quotes them without it, so `"Number of convulsions in this illness" = "1 convulsion"` would match
nothing. A leading bullet is stripped from the cell.

## The classification is the output

The kit states each of its classifications as a `Derived` row of its own — 72 of them on
`CHE.B23.Classification` — grouped by the `Data element subcategory` column into the assessment
that reaches it. A `Derived` row is a conclusion the kit's algorithm computes from the signs
recorded before it, which a form can prompt for but not reach, so by the rule that drops the PNC
kit's 109 `Annotation` rows all 72 would drop.

That would leave the program unable to compute a single indicator the kit publishes. **All 33 of
its Annex C indicators count a classification by name:**

```
CHE.IND.4   COUNT of consultations of infants and children with "age" = 0–59 months
            with "Pneumonia" classification recommended
CHE.IND.6   COUNT of consultations with infants and children with "age" = 0–59 months
            with "Severe dehydration" classification recommended
```

A health worker following IMCI records the classification — it is what the chart booklet has them
tick and what decides the treatment. So `CLASSIFICATIONS` carries each group as one Select-all
question whose options are that group's classification labels verbatim: 17 questions, 72
classifications, and the option strings are the strings the indicators quote.

This is the one place where the reader builds a question the dictionary has no row for. The domain
names each group and the question it becomes, because the subcategory values are prose; a group
the domain has not named is an error rather than something passed over, so a WHO revision adding
one announces itself.

**The 28 `Derived qualifier` rows are not carried.** Each qualifies one classification —
`Pneumonia`, then `With wheezing` — and the kit repeats a qualifier under every classification it
applies to. `With wheezing` appears three times in the cough group and `Fever present every day
for more than 7 days` three times in the fever group; flattened into one option list they collide
with each other and lose the classification they qualified. No Annex C indicator counts one.

## One tab, seven groups

`CHE.B24.Group questions` defines seven clusters of questions — the respiratory rate, the oral
fluid test, the inhaled bronchodilator trial, the appetite test, the breastfeeding assessment, the
second temperature measurement and the malaria test — each an untyped heading row carrying an id
with its questions beneath. The process tabs reference a cluster by that id.

This is the TB kit's shared-tab idea with a cluster in place of an element, and stated differently:
where the TB kit writes `Please check "TB.Common" tab for more data element details` in the
multiple-choice column, this kit writes nothing that names the tab at all. The three rows naming
`CHE.B24.DE01` type it `Group questions`, `Group question` and `N/A`. So a reference is identified
by its id resolving to a group on the tab `GROUP_SOURCE` names, not by the spelling beside it —
which is also why all three spellings work without being enumerated.

Ten references expand to 48 questions across four surveys. Unlike a single-element cross-reference,
which takes the referring process's own `Required` flag, a cluster's members each carry their own;
the reference row contributes its label, which heads them.

`CHE.B22.Assessments-Tests` is where this matters most. Five of its seven rows are references, and
the two that are not — `CHE.B24.DE06 Second temperature measurement` and
`CHE.B24.DE07 Malaria test` — are typed there as single elements while `CHE.B24` groups the same
ids into five and nine questions respectively. The group tab's reading wins, since it is the tab
that holds the definitions.

## Deliberate divergence

- **The registration activity is not a survey.** `CHE.A`'s `CHE.A4` / `CHE.A8` / `CHE.A9` /
  `CHE.A11` activity gathers, creates and validates the child's record: national unique
  identification, first, middle and last name, date and time of birth, age, sex, caregiver names
  and relationship, three telephone numbers, the accompanying persons, the biological mother's
  vital status, and the visit date. Tamanu holds all of it natively. Only the `CHE.B3` slice —
  why the child is here — becomes a survey.
- **`CHE.B28.Country Configuration` is dropped.** Its one element is a population mean, which is a
  deployment setting.
- **`setting-malaria` and `setting-hiv` are carried although they describe the site.** They ask
  which malaria tests are available within two hours, whether the RDTs in use allow species
  identification, and what the microscopists are expected to differentiate — the same answers for
  every child at that facility. They are here because the kit marks all eight elements `R` and the
  classification branches read them; a deployment holding them as configuration should drop the
  two surveys rather than ask them at each consultation.
- **The severe-classification summary restates the classifications.** `CHE.B27`'s eleven Booleans
  — `Danger signs`, `PSBI`, `Severe acute malnutrition` — are the composites the treatment tables
  read where a rule turns on more than one classification. They overlap the classification survey
  by design; the kit collects both.

## Dictionary defects carried as found

Reported by every run, and carried rather than corrected, because the labels are the reporting
interface and a correction invented here would not be the kit's.

### A classification labelled as its own opposite

Annex A gives `CHE.B23.DE68` and `CHE.B23.DE70` labels that both end
`with medical complications`, differing only in whether the parenthesis spells out
`weight for age [WFA]` or abbreviates it. Annex B calls `CHE.B23.DE70`
`without medical complications` throughout, in both the classification table and the treatment
table, and refers only `DE68` urgently.

Annex A's label is the typo. The acute malnutrition group therefore carries two options reading
`with medical complications`, and the urgent-referral prompt gates on `DE68`'s label alone.
Annex C's `CHE.IND.17` quotes `DE70` as `without medical complications`, so it reads as a gap.

### The reason for consultation, stated twice

`CHE.A` writes `Reason for consultation` as a `Coding` / `Select one` row with no id, and then
again as `CHE.B3.DE01` with the same label, the same type and the same options cell. Both rows are
typed, so neither the heading rule nor the repeated-id rule reaches them; the three option rows
attach to the second, and the first would import as a mandatory free-text box beside the real
question. The row carrying the id is kept, since it is the one an indicator or a decision rule can
name.

### Two ids used twice on one tab

`CHE.B18-21.Signs <2 mths` gives `CHE.B21S2.DE08` to both `Infant's movements` and
`Young Infant receives food or fluids other than breast milk`, and `CHE.B21S2.DE24` to both
`How are the feeding utensils cleaned?` and `Is infant given any breast milk at all?`. The first
row of each pair is kept. The second `DE24` was the parent of `CHE.B21S2.DE28 Breastmilk also
given` and `CHE.B21S2.DE29 No breast milk at all`, so those two options are orphaned and dropped —
the run reports all four.

### One activity, several wordings

`CHE.A` heads its registration activity five ways, differing only in capitalisation and in whether
a space follows the separating dot: `CHE.A9. Validate child details`,
`CHE.A9.Validate child Details`, and so on. Grouped by their text they would open five screens for
one activity. Case and dot-spacing are now levelled, and where a process takes a slice of a tab
every row of an activity is headed by the first wording the kit used for it — which is what merges
`CHE.B3. Determine reason for consultation` with
`CHE.B3. Determine reason for and type of consultation`.

Punctuation is deliberately not levelled: the PNC kit gives two genuinely different activities the
same id and separates them by a comma. `CHE.B7. DangerSigns` and `CHE.B7/B8/B9. DangerSigns` stay
two activities for the same reason, and the second takes a suffixed heading code.

## Decision support

Annex B states its logic as four decision tables. Two classify — one per age band — and are not
expressible in a survey: a rule reads up to seven inputs spread across the symptom, sign,
measurement and assessment forms and concludes the classification the health worker is about to
record.

The two treatment tables are expressible, because they key on the classification alone:

```
CHE.DT.03.TR04   "Classification" = "CHE.B23.DE03 – Severe pneumonia or very severe disease"
                 ➢ Give first dose of pre-referral ampicillin (IM) and gentamicin (IM)
                 ➢ Refer URGENTLY to hospital
```

That is one input, and it is an option of a question this program carries. Twelve prompts gate on
a recorded classification and carry the kit's own action text, each with a patient issue: danger
signs, life-threatening illness, severe pneumonia, severe dehydration, very severe febrile
disease, mastoiditis, severe eye or skin conditions, severe anaemia, complicated severe acute
malnutrition, possible serious bacterial infection, severe jaundice, and young infant severe
dehydration. Two further prompts carry the immunization and HIV health-promotion actions, with no
issue, because neither is a referral.

Carried are the classifications whose treatment begins with referral or a pre-referral dose, which
are the ones where a prompt arriving late is the harm. The rest of the kit's treatment rules are
dosing tables and belong with the prescription rather than on the assessment form.

A rule names the classification question **by question code** rather than by data element id,
because a classification question is one the reader builds from a group of the kit's rows and the
dictionary has no single id for it.

## Annex C coverage

Checked by [`../annex_c_coverage.py`](../annex_c_coverage.py), which compares the element labels
and option strings an indicator's computation quotes against what the forms carry:

```bash
python annex_c_coverage.py --domain che --list gap
```

| | |
|---|---|
| covered by the forms | 11 |
| gap in the forms | 4 |
| computation not quoted | 18 |
| no computable numerator | 0 |

**Eighteen of the 33 computations quote nothing.** They state the numerator in prose — `COUNT of
consultations with infants aged 0–59 months with any severe classifications (0 to <2 months:
severe jaundice; possible serious bacterial infection …)` — listing the classifications they count
without quoting any of them. No reading turns prose into an element list, so the check cannot
answer either way; this is not a gap, and widening the selection would not move it. The ANC kit
states all of its numerators this way.

The four real gaps are all Annex C spelling a classification differently from Annex A:

| Indicator | Annex C quotes | Annex A's label |
|---|---|---|
| `CHE.IND.14` | `Feeding problem or low WFA` | `Feeding problem and / or low WFA` |
| `CHE.IND.17` | `… without medical complications` | `… with medical complications` (see above) |
| `CHE.IND.18` | `Moderate malnutrition` | `Moderate acute malnutrition` |
| `CHE.IND.22` | `Some anaemia` | `Anaemia` |

Each is a defect in one annexe or the other rather than a missing question. The comparison is left
strict: loosening it to match near-spellings would turn every future genuine gap into a green
tick.

## What cannot be encoded

- **The classification itself.** The kit computes it from up to seven inputs across four forms;
  Tamanu records what the health worker concludes. This is the whole reason the classification is
  a question rather than a derived value.
- **The age band.** Every assessment in the kit forks on whether the child is under two months,
  and the forms are split accordingly, but nothing switches a health worker between them. Tamanu
  holds the date of birth, so a deployment can compute the band; the form cannot select itself.
- **`CHE.B24.G.DE17 Inhaled bronchodilator trial results`** is typed `Coding` with no option list
  in the dictionary — country-configured, in the kit's own terms — so it is emitted as free text.
  A deployment supplies the list.
- **`CHE.B24.G.DE16 How did the child last drink?`** is typed
  `Coding (use the same coding as for the oral fluid test results)`. The kit names the value set it
  borrows in the type column rather than giving the element options, and there is no mechanism for
  one element to take another's; it is carried with the options the dictionary gives it.
- **The dosing tables.** Annex B's treatment rules give weight-banded doses for every drug the
  programme uses. Those belong to Tamanu's prescribing, not to an assessment form.
- **Annex D** is a conformance checklist for the deployment, not form content.

## Fetching the components

Not committed — third-party spreadsheets WHO publishes at stable URLs, ignored via
`<domain>/annexes/`. [`domain.py`](domain.py) records the URL and the sha256 of each, and the
generator prints the fetch command when one is absent:

```bash
mkdir -p forms/who-dak/che/annexes
curl -sL -o "forms/who-dak/che/annexes/CCC DAK_core data dictionary.xlsx" \
    https://raw.githubusercontent.com/WorldHealthOrganization/smart-dak-ccc/v1.0.0/input/dictionary/CCC%20DAK_core%20data%20dictionary.xlsx
```

A checksum mismatch is a warning rather than an error: WHO may have revised a component, and the
regenerated spec should be reviewed before it ships.
